# Техническое задание на единый набор данных для Power BI

**Проект:** ReportScriptEXCEL IKTT 2 STAGE  
**Версия:** 2.0  
**Дата:** 07.09.2026  
**Начало второго этапа:** 01.09.2026 00:00 UTC+05:00

## 1 Цель

Нужно создать один Excel файл, который Power BI сможет обновлять без ручной перестройки запросов и связей. Файл должен объединять перевозки, пункты пропуска и текущее положение навигационных пломб.

Пользователь передаёт три логических источника:

1. большую общую выгрузку перевозок;
2. реестр пунктов пропуска с координатами;
3. единый снимок пломб с владельцем, текущим местом, адресом и координатами.

Отдельная ЖД выгрузка, старый агрегированный отчёт и четыре режима расчёта в этой архитектуре не используются. Автомобильные и железнодорожные перевозки определяются по большой выгрузке. Один запуск формирует один Power BI файл с одной стабильной схемой.

## 2 Основное архитектурное решение

Power BI не должен подключаться напрямую к десяткам неоднородных файлов. Перед загрузкой создаётся один нормализованный Excel файл со стабильными именованными таблицами.

```text
Большая выгрузка перевозок ─┐
Реестр пунктов и координат ─┼─> Нормализация и проверки ─> power_bi_dataset.xlsx ─> Power BI
Снимок пломб               ─┘
```

Папка Status_Automation может использоваться для подготовки третьего источника. Она не является отдельным набором таблиц Power BI. Из неё следует сформировать один файл `seal_power_bi_snapshot.xlsx`.

## 5 Поток обработки

1. Найти три входных файла по структуре заголовков, а не только по имени.
2. Записать имя, размер, дату изменения и контрольную сумму каждого файла.
3. Проверить обязательные столбцы и типы.
4. Отфильтровать перевозки по `created_at >= 01.09.2026 00:00 UTC+05:00`.
5. Оставить последнюю версию каждого `transportation_id`.
6. Нормализовать страны, статусы, типы перевозки и тип транспорта.
7. Разбить поля с несколькими пломбами или номерами поштучно.
8. Сопоставить пункты через `point_alias_input` и сохранить `point_id`.
9. Сопоставить пломбы по точному `seal_number`.
10. Сформировать выходные таблицы и журнал качества.
11. Сверить итоги авто плюс ЖД с общим итогом.
12. Сохранить один `power_bi_dataset_<timestamp>.xlsx`.

## 6 Правила дат и статусов

`Дата создания` является датой начала перевозки. Только она определяет попадание перевозки во второй этап.

`Дата обновления` является датой появления текущего статуса. Для завершённой перевозки она становится `completed_at`. Для активной перевозки она остаётся `status_changed_at` и не считается датой завершения.

| status_group_code | Условие |
|---|---|
| ACTIVE | Исходный статус означает активную перевозку |
| COMPLETED | Исходный статус означает завершённую перевозку |
| OTHER | Известный статус вне двух основных групп |
| UNKNOWN | Статус не распознан |

Активные и завершённые перевозки считаются отдельно. Пустой статус не заменяется активным.

## 7 Правила типов перевозки

| movement_type_code | Название | Условие |
|---|---|---|
| TRANSIT | Транзит | Перевозка проходит через Казахстан |
| EXPORT | Экспорт из РК | Начало в Казахстане, завершение вне Казахстана, тип экспорт |
| MUTUAL_TRADE | Взаимная торговля из РК | Начало в Казахстане, страна назначения ЕАЭС, тип взаимная торговля |
| OTHER | Прочая перевозка | Известный тип вне целевых групп |
| UNKNOWN | Не определено | Тип не распознан |

Одна перевозка получает один основной `movement_type_code`. Пересечение целевых групп запрещено и фиксируется как ошибка качества.

## 8 Определение авто и ЖД

Источник для обоих видов транспорта один: большая общая выгрузка.

Приоритет классификации:

1. нормализованное значение столбца `Тип транспорта`;
2. формат одного или нескольких значений из `Номера ТС`;
3. вид сопоставленного пункта в реестре;
4. `UNKNOWN`, если источники не дают однозначного результата.

Если номера перечислены через `/`, каждый фрагмент проверяется отдельно. Наличие автомобильного номера не должно автоматически превращать явно железнодорожную перевозку в автомобильную. Конфликт между столбцом, номером и пунктом получает `transport_mode_quality_code = CONFLICT`.

## 14 Правила отсутствующих данных

Пустое значение означает, что источник не дал данных. Ноль означает рассчитанное отсутствие событий. `UNKNOWN` означает, что значение присутствовало, но не было распознано.

Неизвестный пункт, страна, транспорт, статус или владелец не удаляется. Исходное значение записывается в `dq_issues` вместе с именем файла и номером строки.

## 15 Контроль качества

Перед сохранением выполняются проверки:

1. нет перевозок с `created_at` раньше начала второго этапа;
2. ключ `transportation_id` уникален в `fact_transportation`;
3. ключ `seal_number` уникален в одном снимке `fact_seal_snapshot`;
4. нет отрицательных количеств;
5. все `point_id`, `company_id` и `source_id` существуют в справочниках;
6. координаты находятся в допустимых диапазонах;
7. координаты `0,0` преобразованы в пустые значения;
8. AUTO плюс RAIL плюс UNKNOWN равно общему количеству;
9. пломбы из большой выгрузки сопоставлены с снимком или получили `NOT_FOUND`;
10. дата координаты не позже даты формирования снимка;
11. пустые значения не заменены нулями;
12. каждый выходной лист содержит именованную Excel Table с постоянными столбцами.

| stage_start_at | 01.09.2026 00:00 UTC+05:00 |
| generated_at | Время формирования файла |
| main_export_updated_at | Дата большой выгрузки |
| point_registry_updated_at | Дата реестра пунктов |
| seal_snapshot_updated_at | Дата снимка пломб |

Если снимок пломб старше допустимого порога, перевозки продолжают формироваться, но показатели текущего положения пломб получают статус `STALE`.

## 18 Критерии приёмки

Результат готов, когда:

1. Power BI подключается к одному выходному Excel файлу;
2. обновление не требует ручного выбора листов или изменения Power Query;
3. транзит, экспорт и взаимная торговля фильтруются по авто и ЖД;
4. карта пунктов использует реестровые координаты;
5. карта пломб показывает только строки с валидными координатами;
6. выбор пункта фильтрует связанные показатели;
7. выбор пломбы показывает владельца, состояние, адрес и текущую перевозку;
8. все неизвестные и конфликтные значения видны в журнале качества;
9. результат сверяется с контрольными итогами большой выгрузки;
10. схема одинакова при каждом запуске.
